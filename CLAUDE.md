# Website — рабочие правила проекта

**Источник правды — код и `second-brain/`.** Навигация — `second-brain/index.md`, процесс — `second-brain/00_system/TASK_WORKFLOW.md`.

## 1. Общение (жёсткое правило)
- **Всё владельцу — по-русски**, любой ответ; другой язык — по его просьбе.
- Варианты — текстом, с плюсами и минусами; **рекомендованный первым, «(рекомендую)»**.
- **«Рекомендую» без доказательства — брак:** проверяемый факт + **контр-проверка** («что увидели бы, будь вывод неверен») + цена ошибки. Нечем доказать — так и скажи.
- **Техвопросы владельцу НЕ задаются** — решай по `decision-defaults` и докажи постфактум; варианты вместо решения — то же нарушение. Исключение: **деньги, аккаунты, необратимое удаление — решение владельца.**
- **Советник, не блокиратор:** возражение одно и ДО исполнения, дальше как сказал владелец; отступление от дефолта — в `second-brain/02_architecture/stack.md`.
- **Скиллы зовёт агент, а не владелец:** подходящий скилл вызывается сам, без команды и без напоминания. Владелец не обязан помнить ростер и набирать `/имя` — забыть имя скилла это его право, а не его промах. «Скажете — вызову», «есть скилл X, применить?» вместо вызова — нарушение. Не уверен, какой из двух, — бери подходящий и скажи какой и почему; ошибся выбором — это дешевле, чем не вызвать вовсе. Единственное, что остаётся за владельцем: выбор дизайн-направления (ниже) и деньги/аккаунты/необратимое удаление.
- **Объясняешь — визуализируй:** любое объяснение владельцу (как устроено, что произойдёт, почему так, было→стало) идёт через навык `visualize`. Стена текста вместо схемы — нарушение.
- **Дизайн выбирает владелец, и спрашивается КАЖДЫЙ раз:** перед вёрсткой любой страницы агент присылает **три** варианта направления живыми примерами (`node tools/design-board.mjs --refs "<описание бизнеса>"` → `artifacts/design-board/index.html`), объясняет словами, что выбор меняет (шрифты, цвет, ритм, характер блоков) и чего не меняет (факты о бизнесе, состав секций, разметку), и ждёт ответа. Три, а не весь каталог и не один. Ключ `DIRECTION=` — внутренняя кухня, владельцу называются номер и имя. Вёрстка без ответа владельца — нарушение; автовыбор `pickDirection` законен только на явное «на твой вкус».
- **Доска идёт с референсами, флаг `--refs` обязателен** (решение владельца 2026-08-12): под тремя вариантами блок «Откуда смотрели» — живые сайты с Awwwards по разделу ниши и кадры с Dribbble. Доска без референсов — нарушение: владельцу не на что опереться, кроме наших же карточек. Awwwards даёт ссылки на живые сайты (с них снимаются настоящие шрифты и цвета), Dribbble — только картинки макетов (настроение и композиция, живого CSS в них нет). Ни одного текста и ни одного факта с референсов на страницу клиента не переносится — §12 сильнее.

## 2. Без нарративных комментариев в коде
Код самодокументируем. Объясняющие комментарии не пиши, встреченные удаляй. Разрешены ТОЛЬКО функциональные директивы (`eslint-disable*`, `@ts-expect-error`). _(Хук `check-no-narrative-comments`.)_

## 3. Ship-On — выкатываем включённым
Фича идёт в прод включённой; «включим потом» запрещено. Законных флага два: kill-switch и решение владельца. Флаг — строка в `docs/operations/feature-flags.md`.

## 4. Конфиг: секреты в ENV, крутилки — в рантайм-настройки
В ENV — ТОЛЬКО секреты и строки подключения. Пороги, лимиты, флаги, TTL, веса — динамический конфиг `admin → env → code-fallback`. Доступ к env мимо схемы запрещён. _(Хук `check-no-raw-env`.)_

## 5. Знание vs планы
Факт → `second-brain/`; замысел → `plans/`. Что куда — `second-brain/00_system/STRUCTURE_RULES.md`.

## 6. Два контура работы + жёсткий gate
**A — «первый скелет»**: `idea-interviewer` → `project-bootstrap`, скелет в первый день.
**B — «каждая следующая фича»**: `feature-analyst → solution-blueprint → tz-author → tz-orchestrator → qa-user-tester → strict-production-review-gate`.
**Gate:** ТЗ не пишется, пока нет `plans/architecture/<feature>.md` со `status: approved`. Владелец ставит `approved`, агент — никогда сам.
**Глазами пользователя:** «готово» по фиче с UI — только после прохода `qa-user-tester` через браузер, не по коду и не по тестам.
**Лёгкая тропа:** 1–2 файла без развилок — прямой маршрут, критерий в `core-engineering-standards`.

## 7. Реестр не-сделанного
Отложил / вскрыл пробел / заблокирован → сразу строка в `second-brain/04_not-done/README.md`: четыре поля (дата · что · **почему**, включая «кто разблокирует» · ссылка на детали), ≤400 символов.

## 8. Завершение работы по триггеру
Триггеры: `git push` · «всё/спасибо/ок» · >10 рефлексий. Сработал — делаешь ПЕРВЫМ, до ответа владельцу. **Рефлексию и знание пишет агент сам; предложить «написать рефлексию?» вместо того, чтобы её написать, — нарушение.** Шаги — post-push-хук и `second-brain/00_system/UPDATE_AFTER_CODE_CHANGE.md`: знание, рефлексия, `CHANGELOG.md` кита, деплой-лог, дистилляция.
Плюс «запомнить решение»: развилка по типу там же, `memory/*.md` коммить с работой.

## 9. Git
- Коммить ТОЛЬКО своё; никогда `git add .`/`-A` — пути явно. Untracked не трогать.
- **Коммит оформляется САМ, без вопроса владельцу** (решение владельца 2026-08-12). Файл, где правки агента соседствуют с правками владельца, тоже коммитится — молча оставлять работу незакоммиченной запрещено. Спрашивать «оформить коммит?» — нарушение.
- **Чекпоинт-коммиты:** каждая зелёная фаза = коммит.
- `git push` — только с явным подтверждением на КАЖДЫЙ push; рефлексия пушится сразу после основного.
- Формат: `тип(область): описание`.

## 9а. Стоп-кран отладки (жёсткое правило)
Две неудачные попытки исправить одну проблему → быстрые фиксы ЗАПРЕЩЕНЫ, переключайся в `debug-recovery`. Развалено заплатками — откат к зелёному чекпоинту.

## 9б. Гигиена сессий
Новая задача — свежая сессия; свежая и на КАЖДЫЙ стык цепочки §6. **Сессия звена НЕ закончена, пока промпт следующего звена не записан в `plans/handoff/<feature>-handoff.md`** — без отсылок к чату; следующего звена нет — так и напиши.

## 10. Стек и команды
- Рантайм/пакеты: `npm`. Установка: `npm install`. Dev: `npm run dev`.
- Перед завершением: `npx tsc --noEmit` · `npm run lint` · `npm run build` · `npm test`. Билд красный — «готово» не докладывай.
- БД: изменение схемы = версионируемая миграция.

## 10а. Не изобретай велосипед (жёсткое правило)
Перед кодом: **[1] RepoBrain** (`make_context_capsule`) → **[2] `context7`/web** → **[3] пиши сам**. 10 своих строк вместо 1 строки библиотеки — дефект ревью.

## 11. Тулинг
Чем искать — `.claude/CLAUDE.md`. Деплой и стенды — `docs/operations/`.

## 11а. Суб-агенты (жёсткое правило)
- **Читать веером, писать в одиночку:** спавни на read-only ветках (картография, ресёрч, ревью); реализацию делай сам.
- **Хватает одного — бери одного:** «If one subagent can complete the task, use one rather than several, and keep spawn counts low».
- **Проверяющий ≠ автор:** ревью своего кода — свежим контекстом, и баг обязан быть доказан.
- Веера нет → делай сам и честно скажи об этом.

## 12. Сервис не сочиняет факты о бизнесе клиента (жёсткое правило)
На странице клиента нет ни одного утверждения, которого клиент не сказал во входе: цены, стаж, число клиентов, награды, имена, отзывы, адрес, телефон, часы, гарантии. Нет во входе — плейсхолдер, а не выдумка. Город не терять и не подменять. Правило наследует **каждый** режим, порождающий текст (генерация, конструктор, разбор чужого сайта, правка кликом); режим без него — блокер на ревью. Детали и основания — `second-brain/02_architecture/no-invented-facts.md`.
