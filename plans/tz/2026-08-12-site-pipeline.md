# ТЗ: три недостающих этапа конвейера сайта

## Цель

Конвейер из девяти этапов существует на шести. Три отсутствуют: маршрут по типу сайта,
критик со зрением, проверка фактов. Без первого структура страницы одна на всех
(`DEFAULT_STRUCTURE`, восемь секций). Без второго качество меряет только человек в браузере.
Без третьего инвариант «не сочинять факты о бизнесе клиента» живёт строкой промпта, которую
модель уже один раз разменяла на объём текста.

## Зачем

| Болезненное состояние | Чем решение лучше | На чём стоит |
|---|---|---|
| Стоматология, фотограф и автосервис получают одинаковый скелет страницы | Тип сайта выбирается явно и определяет секции, разметку, слоты медиа, дирекшен, движение | `claude-seo` маршрутизирует проверки по вертикали бизнеса — этап 2, сделанный до нас |
| Качество страницы знает только человек, смотрящий в браузер | Критик смотрит на скриншот, ставит балл, перечисляет дефекты, страница пересобирается | +96% точности и вид 3.0 → 3.9 на WebGen-Agent; независимо +17.8% за три цикла на WebDev Arena |
| Запрет выдумывать факты — текст в промпте | Отдельный этап сверяет каждое утверждение со строкой брифа | Прогон 2026-08-12: требование объёма дало 4+ выдуманных факта, оговорка в промпте не удержала |

## Фаза 0 — Одна страница до «вау» (решение владельца 2026-08-12)

**Ценность.** Как владелец, получаю одну страницу, которую не стыдно отдать клиенту,
и понимаю на ней, что именно критик умеет ловить, — вместо среднего качества по двадцати нишам.

**Мишень — `artifacts/sites/grigory-borisov/index.html`**: свадебный фотограф, Алматы,
36 реальных снимков, `check-page.mjs` даёт `✓ проверки пройдены` (0 блокирующих, 2 замечания).
Выбрана как единственная страница про реальный бизнес: «вау» тут добывается доводкой,
а не починкой поломанного.

**Что входит.** Критик (Фаза 2) применяется к этой странице, балл и дефекты снимаются,
страница пересобирается до потолка петли. Замечания `check-page.mjs` закрываются:
сетка `.steps li` с `::before` в первой ячейке.

**Что НЕ входит.** Двадцать входов и доля годных по нишам — снято владельцем 2026-08-12,
строка в реестре не-сделанного. Прогон, стоящий денег, на этой фазе не нужен.

**Acceptance.**
- `node tools/check-page.mjs artifacts/sites/grigory-borisov/index.html` → `✓ проверки пройдены`,
  замечаний не больше одного (`FAQPage` остаётся сознательно).
- Балл критика по странице снят до доводки и после; вторая цифра выше первой.
- Владелец смотрит страницу в браузере и говорит «вау» либо называет, чего не хватает —
  это единственный критерий приёмки фазы, машинного здесь нет и быть не может.

`Закрывает: R1`

## Фаза 1 — `tools/site-routes.mjs`: маршрут по типу сайта — ОТЛОЖЕНА (В4)

> Маршруты окупаются на втором и последующих сайтах: их смысл — не собирать стоматологию
> и фотографа по одному скелету. Пока делаем одну страницу, маршрут у неё ровно один
> («Работа глазами»), и таблица из четырёх записей не работает ни на что.
> Возвращаемся, когда беремся за второй сайт другой ниши. Контракт ниже дописан и готов
> к реализации без переоткрытия — стартовать по слову владельца.
>
> Строка в реестре не-сделанного: 2026-08-12.


**Ценность.** Как клиент с автосервисом, получаю страницу со структурой автосервиса,
а не универсальный скелет, одинаковый со стоматологией и фотографом.

**Файлы.** Новый `tools/site-routes.mjs`. Правка одной строки `tools/probe-site-gen.mjs:152`
(якорь `const structure = dir.structure ?? DEFAULT_STRUCTURE;` — номер строки на момент
написания, перед правкой перечитать). Формат модуля берётся с соседнего `tools/niche-reference.mjs`.

**Контракт.**

```js
export const ROUTES = {
  'usluga-ryadom':  { name: 'Услуга рядом',   sections: [...], schema: ['LocalBusiness', 'FAQPage'],
                      media: { max: 4, kinds: ['работа', 'место'] }, direction: ['clinical', 'industrial'], motion: 'landing' },
  'rabota-glazami': { name: 'Работа глазами', sections: [...], schema: ['ProfessionalService', 'FAQPage'],
                      media: { gallery: true }, direction: ['gallery', 'editorial'], motion: 'story' },
  'tovar-i-mesto':  { name: 'Товар и место',  sections: [...], schema: ['LocalBusiness', 'Product'],
                      media: { kinds: ['продукт в действии', 'крупный план'] }, direction: ['organic', 'productstage'], motion: 'showcase' },
  'spetsialist':    { name: 'Специалист',     sections: [...], schema: ['Person', 'ProfessionalService', 'FAQPage'],
                      media: { portrait: true }, direction: ['formal', 'swiss', 'luxe'], motion: 'interface' },
};

export function pickRoute(input) { /* → { key, route, why } */ }
export function structureBlock(route) { /* → строка секций для промпта, формат DEFAULT_STRUCTURE */ }
```

`pickRoute` выбирает по тому же тексту описания, по которому сегодня выбирается профиль ниши.
Поле `why` — строка с сработавшими признаками, она уходит в `stderr` логом, как это делают
остальные слои (`[движение] пресет …`, `[дизайн-система] лестницы из …`).

**Что НЕ входит.** Пятый маршрут. Изменение `nicheProfile` — профиль отвечает за «как выглядит»,
маршрут за «из чего состоит», это разные оси (Р2 архитектуры).

**Acceptance.**
- `node -e "import('./tools/site-routes.mjs').then(m=>console.log(Object.keys(m.ROUTES).length))"` → `4`.
- Двадцать входов пробы разложены по маршрутам, ни один не получил `null`; таблица
  «вход → маршрут» приложена к фазе.
- Контрольные пары: `автосервис только для японских машин, Казань` → `usluga-ryadom`;
  `фотограф, снимаю семьи и детей` → `rabota-glazami`; `пекарня, хлеб на закваске` → `tovar-i-mesto`;
  `психолог, работаю со взрослыми` → `spetsialist`.
- Негативный: пустая строка на входе → бросает ошибку с текстом, не отдаёт маршрут по умолчанию.
- `grep -c "DEFAULT_STRUCTURE" tools/probe-site-gen.mjs` → объявление осталось как запасной путь,
  подстановка идёт через маршрут.
- `npx tsc --noEmit` · `npm run lint` зелёные.

`Закрывает: R2, R3`

## Фаза 2 — `tools/page-critic.mjs`: глаза страницы

**Ценность.** Как владелец, получаю страницу, которую уже посмотрели и переделали до меня,
и вижу балл с перечнем дефектов вместо «кажется, криво».

**Файлы.** Новый `tools/page-critic.mjs`. Обвязка best-of-3 вокруг `tools/probe-site-gen.mjs`
без правки его тела.

**Контракт.**

```js
export async function critique(htmlPath, { widths = [390, 1440] } = {}) {
  // рендер playwright → скриншот на каждой ширине → запрос модели со зрением по рубрике
  return { score: 0..5, defects: [{ where, what, severity }], shots: [...] };
}
export async function bestOfThree(generate, { threshold = 4.0, tries = 3 }) { /* → лучшая версия + журнал попыток */ }
```

**Рубрика — половина чужая, половина своя (Р3 архитектуры).**
Общая часть (читаемость, корректность, вид) берётся опубликованной из WebGen-Bench /
WebDev Arena. К ней добавляются наши инварианты, которых нет ни в одной чужой рубрике:
город на месте · плейсхолдеры видны и не выданы за факты · ни одного выдуманного факта.

**Что НЕ входит.** Дообучение модели. Больше трёх попыток — обе работы мерили ровно три
цикла и дальше не смотрели (Р4). Замена `check-page.mjs` — разбор разметки остаётся на нём.

**Acceptance.**
- На заведомо сломанной странице (шапка наезжает на первый экран при 390px) балл ниже 4.0
  и в `defects` есть запись с `where`, указывающим на шапку.
- На `artifacts/core-probe/site-gen/000.html` (ноль дефектов по `check-page`) балл не ниже 4.0.
- `bestOfThree` при трёх вызовах генератора возвращает версию с максимальным баллом и журнал
  из трёх строк; при первой же версии выше порога — не тратит вторую попытку.
- Скриншоты сохраняются на диск, путь в `shots`; файл существует после прогона.
- **Порог качества выхода: доля годных не ниже числа из Фазы 0 на тех же 20 входах.**
  Ниже порога поведение продукта: клиент видит страницу с пометкой «черновик» и кнопкой
  «собрать заново»; заложено 3 попытки; доля заявок, уходящих в ручную доработку при
  измеренной доле годных, — не выше 10%.

`Закрывает: R4, R5, R6`

## Фаза 3 — скилл `fact-check`: сверка утверждений с брифом

**Ценность.** Как клиент, не получаю на своей странице ни одного факта, которого не говорил:
ни цены, ни стажа, ни числа клиентов, ни наград.

**Файлы.** Новый `.claude/skills/fact-check/SKILL.md`. Правок кода нет.

**Что входит.** Каждое утверждение готовой страницы сопоставляется со строкой брифа.
Нет строки — плейсхолдер, а не выдумка. Город не теряется и не подменяется.
Это исполняемая форма инварианта `second-brain/02_architecture/no-invented-facts.md`,
который сегодня живёт только текстом в промпте генератора.

**Что НЕ входит.** Юридическая сторона (ФЗ «О рекламе» ст. 5) — открытая строка в реестре
не-сделанного с 2026-08-10, разблокирует владелец. Правка текста страницы скиллом:
он выносит вердикт, переписывает — сборщик.

**Acceptance.**
- На странице с фразой «более 5000 пациентов» при брифе без этого числа — вердикт «выдуман»
  с цитатой фразы и указанием, какой строки брифа не хватает.
- На странице, где город из брифа заменён на соседний, — вердикт «город подменён».
- На чистой странице — «12 утверждений, 12 подтверждены брифом, N плейсхолдеров на месте».
- Скилл вызывается по описанию задачи, а не только по имени: проверяется формулировкой
  «сверь факты на странице с тем, что сказал клиент».

`Закрывает: R7, R8`

## Требования

| # | Требование (EARS) |
|---|---|
| R1 | Когда фаза приёмки требует порог, система shall брать число из артефакта пробы ядра с датой замера не старше даты последнего изменения генератора |
| R2 | Когда на вход приходит описание бизнеса, система shall назвать один из четырёх маршрутов явно и залогировать признаки выбора |
| R3 | Если маршрут выбран, then структура секций, тип разметки, слоты медиа, дирекшен и пресет движения берутся из его записи, а не из `DEFAULT_STRUCTURE` |
| R4 | Когда страница собрана, система shall отрендерить её на 390px и 1440px, снять скриншоты и получить балл от 0 до 5 со списком дефектов |
| R5 | Если балл ниже 4.0, then страница пересобирается; всего попыток не более трёх; возвращается версия с максимальным баллом |
| R6 | Если после трёх попыток балл ниже порога, then клиент видит страницу с пометкой «черновик» и кнопкой «собрать заново» |
| R7 | Когда страница готова, система shall сверить каждое утверждение со строкой брифа и пометить каждое как подтверждённое, плейсхолдер или выдуманное |
| R8 | Если утверждение не подтверждается брифом, then оно заменяется плейсхолдером, а не остаётся на странице |

## Граф фаз

```
Фаза 2 (критик) ──> Фаза 0 (одна страница до «вау») ──> вердикт владельца
Фаза 3 (fact-check) ─────────┘

Фаза 1 (маршруты) — отложена до второго сайта (В4)
```

Порядок изменён решением В4. Первым пишется критик — без него доводить страницу нечем.
Фаза 3 независима, идёт параллельно. Фаза 0 — применение критика к живой странице и вердикт
владельца глазами. Фаза 1 вне текущего забега.

- **RBAC / tenancy** — `[N/A: инструменты запускаются локально из командной строки, чужих данных не касаются]`
