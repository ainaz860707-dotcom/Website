# Витрина работ: 14 репозиториев вместо папки `artifacts/`

## Зачем это существует

`artifacts/` — 531 МБ и в git не входит (`.gitignore`): это выход генераторов, он пересобирается
командой. Но именно там лежат готовые страницы, которые владелец показывает людям. Показать
локальную папку нельзя, а весь `Website` целиком — это код и внутренние заметки, а не витрина.

Поэтому каждая законченная работа вынесена **отдельным публичным репозиторием** с включённым
GitHub Pages: ссылка ведёт не на исходник, а на живую страницу.

## Правила выноса

1. **Не копируется целиком.** Из копии вырезаются `node_modules`, `dist`-мусор и сырые
   3D-исходники: `jeweler` весил 185 МБ из-за `scorpion.obj` (89 МБ) и `СКАРПИОН.obj.zip`
   (96 МБ) — в вебе работает `scorpion.glb` на 676 КБ, остальное лишнее. После чистки — 716 КБ.
2. **Pages включается через API**, не руками: `gh api -X POST repos/<owner>/<repo>/pages
   -f 'source[branch]=main' -f 'source[path]=/'`. Сборка занимает до минуты — сразу после
   вызова адрес отвечает `404`, это не ошибка.
3. **Нет `index.html` — Pages отдаёт `README.md`.** Jekyll собирает его в корневую страницу.
   Для таких репозиториев в витрине даётся прямая ссылка на нужный файл, а не на корень
   (`hero-video-scenes/scene-video.html`).
4. **§12 действует и здесь.** Демо-страницы уезжают с плейсхолдерами (`[Имя Фамилия]`,
   `[город]`) — подставлять вымышленные имена ради красоты витрины запрещено.
5. **Личное не выносится.** Кадры из референсных Reels владельца, скриншоты рабочих сессий и
   отчёты остаются локальными.

## Как обновить работу в витрине

Репозитории — независимые копии, автоматической синхронизации с `artifacts/` нет. Обновление:
скопировать изменённые файлы в клон нужного репозитория, закоммитить, запушить. Pages
пересоберётся сам.
