# Референсы при генерации

## Решение владельца

Генератор берёт дизайн не из зашитого списка направлений, а из живых сайтов ниши.
Решение владельца от 2026-08-10; возражение о цене живого прохода на каждого клиента
снято кэшем по нише. Задействованы все три источника за логином, а не один.

## Как устроено

```
описание бизнеса
  → nicheProfile(): признаки текста, а не список ниш → профиль
  → кэш references/niches/<key>.json свежее 30 дней? отдаём его, сети нет
  → иначе ОДИН Chrome с сессией владельца обходит три источника подряд:
       Pinterest  → сайты самой ниши (у кого учиться в этом деле)
       Mobbin     → кураторские сайты (планка качества вёрстки)
       Cosmos     → подписи к картинкам ниши → какие сюжеты в ней снимают
  → extractTokens() по живым сайтам: шрифты, цвета, шкала кеглей, радиусы, кривые
  → synthesizeDirection(): палитра, пара шрифтов, ритм, сюжеты слотов → JSON в кэш
  → probe-site-gen подставляет в промпт вместо встроенного направления
```

Роли не дублируются: Pinterest отвечает «как выглядит эта ниша», Mobbin — «как выглядит
хорошо сделанный сайт вообще», Cosmos — «что в этой нише вообще попадает в кадр».

## Машинные входы, добытые 2026-08-10

| Источник | Вход | Что отдаёт |
|---|---|---|
| Mobbin | `POST /api/search/fetch-search-page-sites`, тело `{searchRequestId, pageIndex, searchQuery:{contentType,type,activeFilterTags,categories,styles,sortBy}}` | имя, tagline, живой домен; фильтры `styles` (Photography/Minimal/Motion/Colorful/Illustration) и `categories` |
| Pinterest | `POST /resource/BaseSearchResource/get/`, form-encoded `source_url=…&data={options:{query,scope:'pins',…,bookmarks}}`, заголовок `x-csrftoken` из куки | ссылка на сайт, домен, `dominant_color`; постранично через `bookmark` |
| Cosmos | GraphQL `api.cosmos.so/graphql`, операция `GetElementsByCategoryV2` | `generatedCaption.text` — описание каждой картинки; в категории Weddings 3223 элемента |

Cosmos не вызывается запросом-конструктором: страница `/explore/<slug>` сама шлёт GraphQL,
скрипт перехватывает ответы через `addInitScript`. Так не нужно повторять их схему и
запрос не ломается при её изменении.

## Почему нужен именно браузер

Все три отвечают только под сессией: Mobbin без куки — `{"error":{"message":"unauthenticated"}}`,
Pinterest — `403 Invalid Resource Request`. Сессии живут в профиле
`ms-playwright-mcp/mcp-chrome-2d32ba4`, детали — [[reference-sources-access]]. Playwright
поднимает этот профиль в headless поверх установленного Chrome (`channel: 'chrome'`),
поэтому движок браузера не скачивается. Один запуск браузера на все три источника.

## Подписи Cosmos на страницу не попадают

Подписи называют реальных людей и бренды («Groom Devin», «dress by JULITA LONDON»). По
инварианту [[no-invented-facts]] на странице клиента таких фактов быть не может. Поэтому
подписи не копируются: `subjectsFromCaptions()` сводит их к типам кадра по словарю
(«кольца и детали», «сборы», «первый танец») и ранжирует по частоте. На страницу уходит
только тип кадра, имена и бренды отбрасываются на входе.

## Что решает признаковый разбор ниши

Раньше `pickDirection` искал слово ниши в списке; не нашлось — дизайн выдавался по остатку
от деления. Профили опираются на признаки: продаёт картинку · еда и ремесло · здоровье ·
документы и деньги · работа руками · обучение. Тату-мастер и флорист попадают в тот же
профиль, что фотограф, не будучи перечисленными.

## Отказы устроены громко

Сессия потеряна, профиль занят окном, Mobbin вернул пусто — генератор пишет причину в
stderr и берёт встроенное направление. Молчаливой подмены нет: строка `[референсы]`
в логе прогона говорит, откуда взялся дизайн.

## Границы

- Точность акцентного цвета — самое слабое место: дефолты фреймворков и цвета кнопок
  мессенджеров (WhatsApp #25D366, Telegram, Facebook) отсеиваются списком `NOT_A_BRAND_COLOR`,
  остальное берётся по частоте. Не нашлось акцента — страница честно монохромная, и для
  свадебной ниши это верный ответ: цвет там приносят снимки.
- Коммерческие шрифты референсов (Caslon Ionic, GillSansNova) на Google Fonts отсутствуют —
  в дирекшене прямо сказано брать ближайшую пару, подстановку делает модель.
- Работает на машине владельца; на сервере сессии нет — строка в `04_not-done`.
