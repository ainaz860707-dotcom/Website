# Слой ревью на уязвимости

## Откуда взято

`github.com/getsentry/skills`, коммит `24fdb83` от 2026-08-08, лицензия Apache-2.0.
Поставлена одна папка из 28 — `skills/security-review`. Справочники внутри производны
от OWASP Cheat Sheet Series под CC BY-SA 4.0; файл атрибуции `LICENSE` лежит внутри
скилла и при обновлении переносится вместе с ним.

Состав: `SKILL.md` + 18 справочников в `references/` (инъекции, XSS, SSRF,
аутентификация, авторизация, криптография, десериализация, supply chain, CSRF,
логирование, файлы, API, misconfiguration, бизнес-логика, обработка ошибок, защита
данных, современные угрозы) + языковые `languages/python.md`, `languages/javascript.md`
+ `infrastructure/docker.md`. Исполняемых файлов нет — 21 markdown, запускать нечего.

Sentry-специфичного внутри нет: `grep -riE 'sentry|getsentry'` по всем файлам скилла
пуст, скилл применим к любому коду.

## Почему имя оставлено конфликтным

У Claude Code есть встроенный скилл с тем же именем `security-review` (описание —
«complete a security review of the pending changes on the current branch»). Проектный
скилл в `.claude/skills/` приоритетнее встроенного, поэтому встроенный перестаёт быть
доступен.

Так решено сознательно: у Sentry 18 предметных справочников против одностраничного
встроенного, и жёстче порог сообщения — «отчитывайся только по high confidence»,
«сначала проследи поток данных по всему коду, потом сообщай», «не сообщай по одному
совпадению шаблона». Цена ошибки, будь вывод неверен: мы потеряли бы более богатый
встроенный скилл — проверяется тем, что у встроенного нет ни одного файла справочника.

Переименование отвергнуто: `description` встроенного и чужого совпадают по смыслу, два
имени в листинге дали бы развилку «какой звать» на каждой сессии.

## Граница с нашим каноном ревью

`strict-production-review-gate` — единый канон ревью по правилам проекта и закрывает
**прод-риски**: доступ, данные, деньги, идемпотентность. `security-review` ищет
**уязвимости**: что сможет сделать атакующий с внешним вводом. Дубля между ними нет.

Порядок при работе с внешним вводом — сначала gate, затем security.

## Что дописано в чужой код

Одна правка: в `description` фронтматтера добавлены русские триггеры («проверь
безопасность», «найди уязвимости», «аудит безопасности», «есть ли SQL-инъекция / XSS /
SSRF») и строка о границе с `strict-production-review-gate`. Автозагрузка скилла идёт
матчингом по тексту `description`, а владелец пишет по-русски — без правки скилл на
русскую формулировку не отзовётся.

Обновление: `git pull` в клоне и повторное копирование папки; правку `description`
переносить заново.
