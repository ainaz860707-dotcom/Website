# Слой картинок

## Зачем понадобился второй канал

Кадры для страниц до 2026-08-14 приходили только через MCP `higgsfield`. Канал держится на
интерактивном OAuth и на триальном плане генерирует **только через MCP**: CLI отвечает
`{"error_type":"only_mcp_usage_on_trial_is_available"}`. Значит из скрипта генерации страницы
картинку взять нечем — нужен человек, который вошёл в сервис в браузере.

BFL решает ровно это: обычный HTTP-ключ в заголовке `x-key`, никакого входа. Подписки нет,
оплата по факту генерации.

## Контракт API (сверен по `https://api.bfl.ai/openapi.json`, а не по памяти)

База — `https://api.bfl.ai` (есть региональные `api.eu.bfl.ai` и `api.us.bfl.ai`).
Заголовок авторизации — `x-key`, не `Authorization: Bearer`.

Схема вызова у всех моделей одна: `POST /v1/<модель>` возвращает `id` + `polling_url` + `cost`,
дальше `GET polling_url` до `status: "Ready"`, кадр лежит в `result.sample`.

| Модель | Эндпоинт | Когда берём |
|---|---|---|
| FLUX.2 klein 4b / 9b | `/v1/flux-2-klein-4b`, `/v1/flux-2-klein-9b` | пробы и черновики, $0.014–0.015 |
| FLUX.2 pro | `/v1/flux-2-pro` | рабочий по умолчанию, $0.03–0.045 |
| FLUX.2 flex | `/v1/flux-2-flex` | когда в кадре нужен читаемый текст |
| FLUX.2 max | `/v1/flux-2-max` | максимальное качество, $0.05–0.07 |
| FLUX 3 video | `/v1/flux-3-video` | видео, $0.06/с в draft, $0.17–0.29/с в HD |
| Инструменты правки | `/v1/flux-tools/erase-v1`, `outpainting-v1`, `deblur-v1`, `vto-v2` | стереть объект, дорисовать края, примерка |

Цена считается по мегапикселям выхода, поэтому `--size` — это деньги, а не только композиция.
Ссылка на готовый кадр живёт **10 минут**: файл скачивается сразу, отдавать этот адрес на
страницу клиента нельзя.

`GET /v1/credits` — бесплатный вызов, он же единственная честная проверка ключа: `grep` по
`.env` показывает лишь наличие строки. Проверено 2026-08-14 — ключ владельца отвечает, баланс
**0 кредитов**, то есть до пополнения любая генерация упрётся в оплату.

## Инструмент

`tools/bfl-image.mjs`:

```
node tools/bfl-image.mjs "<промпт>" [--model pro] [--size 1440x2048] [--ref кадр.jpg] [--count N]
node tools/bfl-image.mjs --balance
```

Правка словами включается флагом `--ref`: локальный файл уходит в `input_image` как
`data:<mime>;base64,…`, адрес в сети — как есть, до восьми кадров (`input_image_2…8`).
Публичный хостинг исходнику не нужен — так же, как в `photo-morph.mjs`.

Порогов в ENV нет: в ENV только `BFL_API_KEY` и необязательный `BFL_BASE_URL` под регион (§4).
Модель, размер, формат, число вариантов — флаги.

## §12 в этом канале

Хвост `no text, no signage, no logos, no watermarks, no faces` дописывается к промпту
**по умолчанию**, а не по памяти агента. Снимается только флагом `--allow-text` и только под
собственные съёмки клиента: вывеска, лицо, логотип, номер машины в кадре — выдуманный факт о
бизнесе и блокер на ревью. См. [[no-invented-facts]].

## Развилка «BFL или Higgsfield»

| Что нужно | Канал | Почему |
|---|---|---|
| Кадр на страницу, фон секции, опорный кадр | BFL | ключ в `.env`, зовётся из скрипта, дешевле |
| Правка готового кадра словами | BFL | у FLUX это основной приём, у нас его не было |
| Ролик | Higgsfield | у BFL видео тоже есть, но пресеты и разбор промпта живут в [[video-layer]] |
| Кадр с типографикой, цифрами, схемой | ни тот ни другой | это Remotion, [[video-layer]] |
