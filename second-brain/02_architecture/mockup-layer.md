# Слой макета: картинка страницы до вёрстки

Между «какой дизайн принят в нише» и «вот живой сайт» появился третий ответ — **картинка
конкретной страницы**. Её рисует внешний инструмент pen.dev, вызывается он скиллом
`pen-mockup`, и живёт он на приставном стуле, а не в конвейере. Ниже — почему именно так.

## Что это за инструмент

pen.dev (High Agency, Inc.) — векторный редактор, встроенный в редактор кода: расширения для
Cursor, VSCode, Windsurf, Antigravity, десктопное приложение и CLI `@pen.dev/cli`. Макет
хранится в `.pen` — текстовый JSON, ложится в git и показывает диффы. Сервис объявлен
бесплатным, платное обещано вводить с предупреждением до списания.

Работает CLI так: `pen --prompt "<фраза>" --out <файл>.pen --export <файл>.png` поднимает
**собственный дизайн-агент на подписке Claude Code**, модель Opus 5. Отдельного счёта нет —
расходуются лимиты подписки.

## Почему это не шаг конвейера

Замер первого прогона (промпт «Главная страница сайта химчистки одежды», 2026-08-17):

| | Макет | Страница генератором |
|---|---|---|
| Время | 5 мин 16 с | 12–18 мин |
| Расход | 1.17 млн токенов, 2.05 USD по тарифам API | 0.67 USD |
| Выход | картинка | HTML: текст, разметка, находимость |

Черновик стоит **втрое дороже готовой страницы** — значит, «дешёвый предпросмотр перед
вёрсткой» из него не выходит, и ставить его по умолчанию нельзя. Остаётся один сценарий,
где он окупается: владелец сомневается в облике и не хочет платить прогоном генератора за
проверку догадки. Сомнения нет — макет пропускается.

Второе ограничение принципиальнее денег: **HTML он не отдаёт**. Синхронизация «дизайн ↔ код»
есть только внутри IDE-расширения, страница о ней в документации пустая. Картинку нельзя
открыть по адресу, её не читает поиск и не цитируют нейросети — сайт по-прежнему делает
только генератор.

## Он читает наш репозиторий

Агент pen.dev стартует с Bash в рабочей папке и ходит по ней сам. В прогоне 2026-08-17 он
без единого слова в промпте выполнил `git show HEAD~1`, прочитал `CLAUDE.md` и `tools/` — и
принёс макет в палитре «золото по чёрному» с плейсхолдерами `[ЦЕНА]`, `[ГОРОД]`, `[XX] лет`
вместо выдуманных цифр, то есть подобрал §12 из наших же правил.

Следствие двойное. Полезное: наши инварианты доезжают до чужого инструмента даром. Опасное:
инструмент видит проект целиком, поэтому запускать его из чужой или чувствительной папки не
стоит, а проверка §12 остаётся нашей — правило наше, соблюдение его агентом не гарантировано.

## Место в маршруте и почему не автовызовом «первым»

Попытка сделать `pen-mockup` первым скиллом на фразу «покажи, как будет выглядеть» провалилась
на семи пробах из семи: побеждали `niche-benchmark` (на любой фразе, где названы дело и город)
и `design-taste-frontend` (на фразах про облик без ниши). Переписывание `description` не
помогло — оба конкурента по нашему же порядку работ обязаны идти раньше.

Поэтому маршрут закреплён передачей, а не силой описания: `niche-benchmark` → доска
направлений → **если сомнение в облике осталось** → `pen-mockup` → генератор. Строка передачи
дописана в конец `.claude/skills/niche-benchmark/SKILL.md`.

## Что проверять в результате

- **Кириллица** — шрифт обязан иметь русские буквы; в прогоне 2026-08-17 взял Cormorant
  Garamond + Inter, квадратов не было.
- **§12** — цены, стаж, телефон, адрес, отзывы должны быть плейсхолдерами.
- **Осиротевшие элементы** — агент оставляет блоки на холсте вне рамки макета, на экспорте
  они видны сбоку; в первом прогоне такой был.

## Вход

Вход в CLI отдельный от браузерного: `pen login --email <почта>` шлёт код письмом,
`pen login --email <почта> --code <код>` его подтверждает. Код одноразовый, и вход на сайте
его сжигает — код из письма идёт сразу в команду, минуя браузер. Сессия хранится в
`~/.pencil`, `pen status` показывает `● Active`.
