# Видео на странице: четыре части промпта → техзадание → вёрстка

Промпт к видеомодели состоит из четырёх частей, и пропуск любой отдаёт решение модели:

1. **Главный объект** — дом, ресторан, автомобиль, бассейн, интерьер, кабинет.
2. **Свет** — Golden Hour, Blue Hour, дневной, пасмурный, утренний, ночной практический.
3. **Движение камеры** — облёт, push-in, панорама, пролёт дроном, POV, статика.
   Самая важная часть: она решает, ляжет ролик под заголовок или укачает.
4. **Где будет использоваться** — hero, фон сайта, scroll scrub, шапка, карточка объекта.

Четвёртая часть — не описание кадра, а **техзадание**: из неё следуют длительность, кадр,
вес, кольцевание и допустимая амплитуда движения. Ролик, снятый «просто красиво», в hero не
встаёт: 15 секунд облёта на 12 МБ — это не первый экран, это проваленный LCP.

Источник структуры — разбор ролика `polinext.production` (2026-08-12), части 1–4 оттуда;
техзадание четвёртой части и правила вёрстки — наши, из `plans/block-reel.md`.

## Каталог значений

```
node tools/video-prompts.mjs --list
node tools/video-prompts.mjs --subject "<объект по-английски>" --light blue --camera push-in --usage hero
```

Отдаёт три блока: **промпт для модели** (английский, части склеены в нужном порядке),
**техзадание** (секунды, кадр, вес, кольцевание, контраст под текст) и **правила вёрстки**.
Промпт руками не пишется: у каждого значения света в каталоге записан контраст под текст, у
каждого приёма камеры — кольцуется он или нет. Это то, что глазами в ролике не видно.

## Порядок вызова

**Сначала `motion-direction`, потом сюда.** Видео уместно в пресетах `landing`, `story`,
`showcase`; в `interface` и `off` видеофона нет — там движется только то, чего касается
человек. Пресет выбирает владелец до генерации, ролик заказывается после.

Связки «назначение → блок» уже собраны в `artifacts/block-reel/index.html`: блок 03 — видео
фоном секции, блок 04 — видео, перематываемое скроллом. Новый ролик вставляется в готовый
блок, а не в новый велосипед.

## Генерация — Higgsfield CLI

Установлен глобально: `@higgsfield/cli` 1.1.23, команды `higgsfield` · `higgs` · `hf`.
Вход — `higgsfield auth login` (браузерный OAuth, аккаунт владельца) и `higgsfield workspace
set <id>`. Без выбранного workspace CLI отвечает «No workspace selected» — это не «нет
входа», проверять `higgsfield auth token` по коду возврата, а не печатать токен в чат.

Порядок работы:

1. Собрать промпт и техзадание — `tools/video-prompts.mjs`.
2. `higgsfield model get <job_type>` — какие параметры принимает модель. Имена параметров
   не сочинять: список моделей меняется быстрее любой записи о нём.
3. `higgsfield generate cost <model> --prompt "…"` — **цена до генерации**, обязательный шаг.
   Названа цена — дальше по §1: тратит владелец, а не агент по своей инициативе.
4. Сгенерировать **опорный кадр** картинкой, посмотреть глазами, и только потом оживлять его
   в видео (`--start-image ./кадр.png`). Так дешевле: перегенерация кадра стоит меньше ролика,
   а композицию видно сразу. Медиа-флаги принимают локальный путь и заливают его сами.
5. `--wait` до готовности, файл в `artifacts/<проект>/media/`, рядом постер — первый кадр
   (`ffmpeg -ss 0 -frames:v 1`).
6. Сжать под бюджет веса из техзадания; не влезло — резать длительность, а не качество.

Тот же сервис доступен и по MCP (`https://mcp.higgsfield.ai/mcp`, вход командой `/mcp`) —
берётся, когда удобнее инструментами, а не командной строкой.

Деньги на генерацию и сам аккаунт — решение владельца (CLAUDE.md §1). Агент не заводит
подписку и не жжёт кредиты пачками: сначала один кадр, показать, потом ролик.

## Запасной путь, когда генерации нет

`tools/stock-video.mjs` — банк Pexels, требует `PEXELS_API_KEY` (ключ вписывает владелец).
Ключа нет — Викисклад: `upload.wikimedia.org`, transcoded 720p vp9 webm, свободные лицензии;
так собран `artifacts/block-reel`. Съёмка клиента, если она есть, сильнее и генерации, и стока.

## Граница по §12 — жёстко

Сгенерированный ролик показывает **родовой** объект, а не помещение клиента. «Кабинет
психолога», «зал ресторана», «фасад загородного дома» — можно. Кадр, который читается как
«вот наш офис», «вот наша команда», «вот наш автомобиль», — выдуманный факт о бизнесе, даже
если ни одного слова на странице не соврали. Хвост промпта закрывает самое опасное:
`no text, no signage, no logos, no readable brand marks, no faces`.

Вывеска, лицо, номер машины, награда на стене в кадре — блокер на ревью, а не мелочь.

## Как ролик встаёт в страницу

Механику не изобретать: она разобрана с живой страницы и записана в
[[../../second-brain/02_architecture/video-layer|слой видео]], готовый код лежит константой
`SCRUB_RECIPE` в `tools/stock-video.mjs` и уходит в промпт генератора дословно. Правило слоя:
**первый экран не играет сам, скролл двигает `currentTime`**, и ровно одно `<video>` на страницу.

Higgsfield добавляет к двум существующим источникам (сток Pexels, своё видео клиента через
`HERO_VIDEO` + `HERO_VIDEO_POSTER`) и к морфу из двух фото (`tools/photo-morph.mjs`, Luma)
третий: ролик, которого не существовало. Постер обязателен у всех четырёх — без него прогон
падает, и это не придирка чекера, а LCP-кадр страницы.

## Приёмка ролика

Считает `tools/check-page.mjs` — брак по любому пункту:

- больше одного `<video>` на странице;
- `<video>` без `muted` или `playsinline` — телефон покажет чёрный прямоугольник;
- `data-src` и `autoplay` одновременно — приёмы исключают друг друга;
- видео без постера; постер первого экрана с `loading="lazy"`, без `alt` или без `width`;
- видео есть, а `requestAnimationFrame` нет — перемотка пойдёт рывками;
- секция `data-hero` ниже 200vh — ролик промотается на первых пикселях и встанет.

Постер — отдельный `<img alt>`, а не атрибут `poster`: атрибут не читается ни поиском по
картинкам, ни краулером нейросети. При `prefers-reduced-motion` перемотки нет вовсе.

Зелёный чекер — не «готово». Глазами через `qa-user-tester`: доезжает ли `currentTime` до конца
на реальной прокрутке, кольцуется ли фон без рывка, читается ли заголовок поверх кадра.
