# Скиллы VibeOS — ростер

Скиллы — автозагружаемые по `description` наборы правил/процедур. Три яруса:
**контур A** (первый скелет), **контур B** (конвейер фич) + **контур X** (стоп-кран), и **опциональные stack-паки**.

## Контур A — «Первый скелет» (новая идея → задеплоенный скелет в день 1)
| Скилл | Роль | Статус |
|---|---|---|
| `idea-interviewer` | распаковка сырой идеи простым языком (ноль техвопросов) + обрезка до walking skeleton → product-brief | ✅ включён |
| `core-probe` | **проба ядра** — замер AI-выхода до постройки обвязки: 10–20 реальных входов, критерий до прогона, три числа, вердикт. Звено **обоих контуров** | ✅ включён |
| `project-bootstrap` | стек/структура/БД/хостинг сам по дефолтам, с доказательством одним экраном; деплой скелета | ✅ включён |
| `decision-defaults` | справочник технических дефолтов (стек доказан ресёрчем 2026-07-14); советник, не блокиратор | ✅ включён |
| `server-access` | доступ к серверу по SSH-ключу вместо пароля (секрета в проекте не существует); пошаговый ввод новичка с ожидаемым ответом на каждом шаге | ✅ включён |

## Контур X — «Стоп-кран» (когда всё сломалось)
| Скилл | Роль | Статус |
|---|---|---|
| `debug-recovery` | правило двух попыток → запрет заплаток → воспроизведи → корневая причина → чистый фикс → регрессионный тест → (или откат к чекпоинту) | ✅ включён |

## Контур B — конвейер качества (каждая следующая фича)
Единый канон: `feature-analyst → solution-blueprint → tz-author → tz-orchestrator → qa-user-tester → strict-production-review-gate`.

| Скилл | Роль | Статус в шаблоне |
|---|---|---|
| `core-engineering-standards` | execution plan перед кодом, минимальные изменения, фазовость, build-гейты, **правило «сложность → маршрут» (лёгкая тропа)** | ⏳ обобщить (шаг 2) |
| `feature-analyst` | доказательный анализ рынка/кода, антигаллюцинация, fan-out, состязательный второй проход → `plans/analysis/` | ⏳ обобщить |
| `core-probe` | **проба ядра** для AI-фичи: без артефакта пробы анализ не получает `status: research-complete`, а ТЗ — «Порог качества выхода» | ✅ включён |
| `solution-blueprint` | архитектура человеческим языком (было→стало + макеты), gate `approved` → `plans/architecture/` | ⏳ обобщить |
| `tz-author` | ТЗ-контракт, Step-0 gate, два прохода + challenge-loop, **acceptance в EARS/GWT** → `plans/tz/` | ⏳ обобщить |
| `tz-orchestrator` | реализация фазами силами суб-агентов, приёмка-лестница, «не верь отчёту агента» | ⏳ обобщить |
| `strict-production-review-gate` | production-review (10 категорий по критичности) — **единый канон ревью** | ⏳ обобщить |
| `qa-user-tester` | обязательная проверка глазами пользователя через Playwright MCP: сценарии из ТЗ/brief, скриншоты, консоль, сверка с блюпринтом | ✅ включён |

## Пак Sentry (внешний, github.com/getsentry/skills, Apache-2.0; справочники — OWASP, CC BY-SA 4.0)

| Скилл | Что | Статус |
|---|---|---|
| `security-review` | ревью на уязвимости по OWASP: 18 справочников (инъекции, XSS, SSRF, authn/authz, крипто, десериализация, supply chain), правило «сначала проследи поток данных, потом сообщай», только high-confidence находки | ✅ включён |

Скилл **перекрывает встроенный** `/security-review` Claude Code (проектные скиллы приоритетнее встроенных) — это осознанно: у Sentry глубже база и жёстче порог по ложным срабатываниям.

Граница с нашим каноном ревью: `security-review` ищет **уязвимости**, `strict-production-review-gate` закрывает **прод-риски** (доступ, данные, деньги, идемпотентность). Дубля нет, порядок — сначала gate, потом security при работе с внешним вводом.

## Решения по ростеру (шаг 2 согласовать)
- **Один канон workflow.** Оркестрированная цепочка (выше) — основной. `bulletproof` (внешний 12-стадийный
  workflow) в дефолт **не включён**: он дублирует цепочку и конфликтует за «источник правды об оркестрации»
  (подтверждено ресёрчем). Если нужен соло-режим для лёгких задач — добавь его отдельно и пропиши в CLAUDE.md
  «когда что».
- **Единый канон ревью** — `strict-production-review-gate`. Дубли (`code-reviewer` из bulletproof, встроенный
  `/code-review`) не плодить.
- **Домен-специфика Коры** (`domain-business-context`, `project-architecture-router`, `dzen-content-research`)
  в шаблон НЕ входит — это контент конкретного продукта.
