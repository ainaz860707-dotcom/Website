# Поиск нового: журнал, обход, разбор референсов

Повторный обход одних и тех же мест — главный способ потратить час и не узнать ничего.
Поэтому у поиска есть память: `second-brain/01_projects/research-journal.md`.

Журнал — не отчётность, а экономия. Он отвечает на два вопроса: «где я уже был» и
«куда ещё не ходил». Без первого проход дублируется, без второго — топчется вокруг
знакомого.

## Порядок прохода

**1. Прочитай журнал целиком.** Таблица «Обойдено» — стоп-лист. Раздел «Куда ещё не
ходили» — список направлений, из него берётся цель прохода.

**2. Возьми одно направление, не пять.** Проход вглубь по одному направлению даёт
применимый результат; проход вширь по пяти даёт список ссылок, который никто не откроет.

**3. Ищи.** Поиск, GitHub, документация, доклады и разборы на видео. Видео не пропускай:
у инженерных докладов и разборов часто есть текстовая расшифровка или конспект, и там
попадаются подходы, которых нет в статьях.

**4. Отсеивай по применимости.** Вопрос к каждой находке один: **что из этого попадёт в
генератор на этой неделе.** Не «интересно», а «попадёт». Не попадает — вердикт `мимо`
с причиной; причина важнее вердикта, по ней следующий проход не пойдёт туда снова.

**5. Запиши в журнал сразу, до отчёта владельцу.** Строка на каждый источник, включая
пустые: «сходил, ничего» — это тоже находка, она закрывает направление. Отработанное
направление убери из «Куда ещё не ходили» и допиши новые, которые вскрылись по дороге.

Журнал, заполненный после разговора с владельцем, заполняется наполовину и по памяти.
Пиши до.

## Разбор референса

Владелец показывает сайт — ссылкой или скриншотом — и говорит «хочу такой же».
«Такой же» почти никогда не значит «копия»: значит «то же ощущение». Задача — вытащить
то, из чего это ощущение собрано, и переложить на его бизнес.

**Машинные входы есть у всех трёх источников за логином** — руками кликать не надо:

```bash
node tools/reference-sources.mjs awwwards "<раздел>"    # ссылки на ЖИВЫЕ сайты — с них снимаются токены
node tools/reference-sources.mjs dribbble "<english>"   # кадры макетов — настроение и композиция
node tools/reference-sources.mjs pinterest "<запрос>"   # сайты самой ниши + доминирующие цвета
node tools/reference-sources.mjs mobbin "<Style>"       # кураторские сайты, планка качества
node tools/reference-sources.mjs cosmos "<slug>"        # подписи к картинкам: что в нише снимают
```

**Awwwards и Dribbble сессии не требуют** — работают везде, включая сервер. Awwwards даёт
ссылки на живые сайты, поэтому с него идёт `reference-tokens.mjs`; Dribbble даёт картинки
макетов, живого CSS в них нет — оттуда берётся только настроение, глазами. Запрос к
Dribbble **обязательно английский**: на русский приходят кадры не по теме.

Остальные три ходят одним запуском Chrome с сессией владельца; форматы запросов и границы —
`second-brain/02_architecture/reference-pipeline.md`. Профиль занят открытым окном —
закрой его `kill -TERM`, иначе браузер не поднимется. Ответ вида `unauthenticated`
или `403` означает потерянную сессию: это пишется в отчёт строкой, а не подменяется
выдачей из обычного поиска.

Подписи Cosmos на страницу клиента не копируются никогда — только тип кадра. Причина
в инварианте «не сочинять факты»: подписи полны реальных имён и брендов.

**По ссылке:**

```bash
node .claude/skills/find-new/scripts/reference-tokens.mjs <url>
```

Скрипт печатает шрифтовые семейства, частотные цвета, шкалу кеглей, радиусы скруглений,
тени и переходы — то есть измеримую часть стиля. Структуру той же страницы даёт
`audit-page.mjs` из `niche-benchmark`.

**По скриншоту:** прочитай изображение и опиши то же самое словами — настроение,
шрифтовая пара, доминирующий цвет и акцент, плотность, ритм секций, один запоминающийся
приём. Скриншот не даёт кода, зато честно показывает то, что видит человек.

**Что делать с разобранным:** сложить в новое направление в `tools/design-directions.mjs`
по формату соседних записей — имя, шрифты, палитра, композиция, деталь, ниши. Разбор,
оставшийся текстом в переписке, не существует.

**Чего не делать:** не копировать вёрстку и тексты. Копия чужого сайта не ранжируется —
поиск показывает оригинал — и это чужая работа. Забираешь принцип: пропорции, контраст,
ритм, приём. Пишешь своё.

## Что считается находкой

Хорошая находка — та, что меняет одну строку в генераторе или добавляет один пункт в
панель SEO/GEO. Примеры уровня, на который целимся:

- готовая библиотека вместо ручного кода (разметка, валидация, публикация);
- приём, который у нас отсутствует и проверяется на нашей же странице;
- инструмент замера, дающий число там, где сейчас догадка.

Плохая находка — «ещё один конструктор сайтов, у них тоже есть SEO». Это наблюдение,
а не находка: из него не следует ни одного действия.

## Формат отчёта владельцу

Коротко и по-русски, без списка ссылок ради списка:

```
Ходил: <направление>
Нашёл применимого: <1–3 пункта, каждый — что даёт нашему генератору>
Пусто: <куда сходил и не нашёл, чтобы закрыть направление>
В журнал записано: <число строк>
Следующее направление: <какое и почему оно>
```

Если применимого нет — так и скажи. Проход без находок при закрытом направлении полезнее
трёх находок «на будущее», которые никогда не откроют.
