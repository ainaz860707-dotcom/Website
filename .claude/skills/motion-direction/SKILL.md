# Движение на сайте: назначение → пресет → проверка

Движение описывается не одним словом, а пересечением осей: **назначение** (зачем оно),
**триггер** (от чего запускается), **технология** (чем сделано), **длительность**
(одноразовое, реактивное, непрерывное, управляемое прогрессом). Каталог в
`tools/motion-directions.mjs` хранит все четыре у каждого приёма, поэтому задача ставится
пересечением осей, а не поиском названия в списке: «появление секции → триггер: вьюпорт →
технология: animation-timeline: view() → управляемая прогрессом».

Главная ось для разговора с владельцем — **назначение**: по ней сразу видно, зачем анимация
нужна и чем её делать.

## Каталог: 24 приёма в трёх группах

**Функциональные — помогают пользователю.** Микроинтеракции · переходы состояний ·
обратная связь · загрузка · навигация · переходы между страницами · интро первого экрана ·
слайдеры и галереи. Самое частое и самое недооценённое: страница без них ощущается не
«строгой», а сломанной.

**Скролл — страница разворачивается по мере чтения.** Появление по скроллу · параллакс ·
закреплённая сцена · горизонтальный ход · прогресс чтения · скроллителлинг. Самая большая
группа и самый частый источник невидимого текста.

**Декоративные и атмосферные — держат настроение.** Кинетическая типографика · SVG-анимация ·
наведение на изображения · курсорные эффекты · атмосферный фон · физика и пружины ·
оживление данных · генеративный холст · WebGL и 3D · эмоциональные мелочи.

Каждый приём в каталоге несёт поле `crawlerRisk` — что он способен отнять у поиска и у
ответов нейросетей. Приёмы с риском `критический` (кинетическая типографика, оживление
данных, WebGL) в промпте несут отдельную оговорку: исходный текст обязан лежать в разметке.

## Шесть пресетов

Пресет — готовый набор приёмов, и именно он выбирается вопросом владельцу.

| Пресет | Что это | Референс | Кому |
|---|---|---|---|
| `off` | движения нет | — | документные страницы, печать, медленная сеть |
| `interface` | движется то, чего касается человек | rauno.me | запись, расчёт, услуги специалиста |
| `landing` | **по умолчанию**: разворачивается по мере чтения | hellomonday.com | посадочная страница бизнеса |
| `story` | скролл ведёт повествование | darkroom.engineering | портфолио, студия, длинная страница услуги |
| `showcase` | живой холст поверх обычной страницы | mont-fort.com, lusion.co | премиальный товар, архитектура, трейдинг |
| `world` | страница и есть сцена | bruno-simon.com, activetheory.net | шоукейс; **не для страницы, которую ищут в поиске** |

Пресеты не лестница «дороже — лучше». `interface` для стоматологии сильнее, чем `showcase`:
в нише, где продают доверие, холст с частицами читается как несерьёзность.

## Вопрос владельцу перед генерацией

Задаётся ДО прогона генератора, одним вопросом через `AskUserQuestion`, вариантов четыре —
не шесть: `world` и `off` в список не выносятся, их владелец называет сам.

```
Какое движение у страницы?
- Как читается (рекомендую) — появление секций по скроллу, живые кнопки, один приём. [landing]
- Спокойное — движутся только кнопки и раскрытия, страница нарисована сразу. [interface]
- Повествование — скролл ведёт: закреплённые сцены, параллакс, курсорные эффекты. [story]
- Витрина — живой холст поверх страницы, частицы или 3D. [showcase]
```

Рекомендованный вариант всегда первый и объясняется одной строкой «почему для этого
бизнеса». Владелец назвал референс («хочу как mont-fort») — пресет берётся из таблицы
референсов выше и вопрос не задаётся вовсе.

Это единственный вопрос владельцу про анимацию. Набор приёмов внутри пресета — техническое
решение, оно принимается по каталогу и доказывается постфактум строкой в отчёте.

## Прогон

```bash
MOTION=story node tools/probe-site-gen.mjs "<описание бизнеса>"
MOTION=landing MOTION_ADD=parallax,cursor MOTION_DROP=kinetic node tools/probe-site-gen.mjs "…"
```

`MOTION_ADD` и `MOTION_DROP` принимают ключи приёмов из каталога. Генератор печатает в
stderr строку `[движение] пресет … приёмов N: …` — по ней видно, что реально ушло в промпт.
Пресет не указан — берётся `landing`.

## Чем делается

У нас страница — один файл без сборщика, поэтому весь каталог, кроме WebGL, делается на
голом CSS: `transition`, `@keyframes`, `animation-timeline: view()` и `scroll()`,
`position: sticky`, `scroll-snap`, `clip-path`, `@view-transition`. Библиотеки анимации в
генераторе запрещены — GSAP, ScrollTrigger, Lenis, Framer Motion, Lottie, AOS.

Индустриальные инструменты (GSAP + ScrollTrigger для скролл-сцен, Lenis для инерционного
скролла, Framer Motion в React, Lottie для иллюстраций от дизайнера, Three.js и R3F для 3D)
названы здесь не для подключения, а чтобы понимать чужие референсы: darkroom.engineering
собран на Next + Lenis + GSAP + Three.js, и повторять его стек нам незачем — CSS
scroll-driven animations закрывают ту же задачу без единого килобайта.

Единственное исключение — Three.js по ESM-импорту на пресетах `showcase` и `world`, и только
ради настоящей трёхмерной геометрии. Частицы, шум и линии за курсором делаются на Canvas 2D
своими руками.

## Два правила, которые нарушают чаще всего

**Анимируются только `transform` и `opacity`.** Ширина, высота, отступы, `top`/`left` в
анимации пересчитывают раскладку каждый кадр — страница дёргается.

**`prefers-reduced-motion` уважается всерьёз.** Не «уменьшить длительность», а выключить:
анимации `none`, сцены не стартуют, появления заменяются готовым видом. От параллакса и
больших сдвигов у части людей реально кружится голова. То же под `@media print`.

## Проверка после генерации

Движение проверяется не глазами, а тем, что осталось от страницы без скриптов. Проверка
запускается сама после каждой генерации и печатает строку `[проверка]`; вручную — так:

```bash
node tools/check-page.mjs artifacts/core-probe/<slug>/<id>.html
```

Строка `✗ скрытие вне .js` — брак вне зависимости от того, как страница выглядит: этот
элемент не увидят ни краулер нейросети, ни режим чтения, ни принтер.

Глазами страница смотрится **экранными снимками с реальным скроллом**, а не полностраничным
скриншотом: `fullPage: true` на scroll-driven странице отдаёт чёрную середину, хотя весь
контент на месте — снимок не прокручивает страницу, а появления живут на
`animation-timeline: view()`. Полстраницы «пропало» на скриншоте — сначала проверь способ
съёмки, потом объявляй дефект.

Замер на живых референсах, 2026-08-10:

| Сайт | Пресет | Текста в HTML | Разметка |
|---|---|---|---|
| mont-fort.com | showcase | 7559 знаков | нет |
| darkroom.engineering | story | 5137 знаков | Organization, WebSite |
| bruno-simon.com | world | 3130 знаков | нет |
| lusion.co | showcase | 2152 знака | нет |
| activetheory.net | world | **69 знаков** | нет |

Вывод, ради которого замер делался: **уровень движения не определяет находимость**.
darkroom.engineering с WebGL, Lenis и 48 скриптами держит 5137 знаков и разметку;
activetheory.net на том же уровне отдаёт машине 69 знаков — цитировать нечего. Разница не
в тяжести анимации, а в том, лежит ли контент в HTML под ней.

## Как добавить приём в каталог

Новый приём — запись в `TECHNIQUES` в `tools/motion-directions.mjs` по формату соседей:
`key`, `group`, `name`, `trigger`, `tech`, `duration`, `cost`, `crawlerRisk` и `rule` —
инструкция генератору в одну-две строки, повелительным наклонением, с конкретными числами
вместо «плавно» и «красиво». Дальше ключ дописывается в `techniques` тех пресетов, куда
приём входит. Приём, оставшийся описанием в переписке, не существует.

## Чего не делать

- Не собирать пресет «побольше приёмов»: `story` с двумя закреплёнными сценами подряд
  превращает чтение в борьбу со скроллом.
- Не подменять контент анимацией: текст, который рисует скрипт, для нейросети не существует.
- Не задавать владельцу второй вопрос про анимацию — набор приёмов решается по каталогу.
- Не тащить библиотеку ради приёма, который есть в CSS.
