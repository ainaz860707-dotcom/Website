Публиковать страницу через Artifact и отдавать владельцу ссылку `claude.ai/code/artifact/...`
запрещено. На просьбу «чтобы открывалось у всех» это не ответ.

**Почему:** такая ссылка живёт в чужом аккаунте, требует нажать «Поделиться», ничего не
говорит клиенту и не может стать сайтом. Владелец сказал прямо: «опять сделал ссылку с
клодом, не надо так» (2026-08-19), уже после того, как я отдал такую ссылку.

**How to apply:** «открывается у всех» закрывается двумя путями, оба без claude.ai:
1) самодостаточный HTML одним файлом (`node tools/inline-page.mjs <страница> <выход> --wrap`)
   — кладётся на Рабочий стол, пересылается в мессенджере, открывается двойным кликом
   на любом телефоне без интернета;
2) настоящий адрес — GitHub Pages в его репозитории `ainaz860707-dotcom/Website`, домен
   клиента, любой хостинг. Это аккаунты и деньги, значит решение владельца по §1: вариант
   предлагается, но не выполняется молча.

**Как это сделано по факту (2026-08-19, владелец подтвердил словом «пуш»):** страница
«Арома клининг» выложена на GitHub Pages в отдельный публичный репозиторий под его же
аккаунтом — `gh repo create <имя> --public --source=. --push`, затем
`gh api -X POST repos/<owner>/<имя>/pages -f 'source[branch]=main' -f 'source[path]=/'`,
сборка около минуты, адрес вида `https://<owner>.github.io/<имя>/`. Две грабли: push в
`main` режет хук, разблокировка `touch .claude/.push-unlock` **отдельной командой** (в одной
строке с push хук срабатывает раньше) и тратится на один push, включая холостой
«Everything up-to-date». Боевой адрес всё равно домен клиента, Pages — витрина.
