Пишешь в `tools/motion-directions.mjs` (или в любой промпт-контракт) готовый кусок CSS — собери из него живой пример, открой браузером и сними **вычисленный стиль** замером, а не глазами. Отдельно прогоняй тач-контекст (`devices['iPhone 13']`) и `prefers-reduced-motion`.

**Why:** 2026-08-12, приём `swap` («смена двух кадров»). Я записал в правило рецепт «на hover цикл замирает на втором кадре: `animation-play-state: paused` и `opacity: 1`» — рецепт неверен: работающая анимация перебивает обычное объявление свойства, и наведение замораживает случайную фазу. Замер показал `opacity` 0.00 на карточке Warm Organic, то есть пустую рамку. Второй дефект того же приёма: правило hover без `@media (hover: hover)` делает блок мёртвым на телефоне — 12 замеров подряд дали 0.00 на iPhone 13. **Паттерн ошибки:** CSS валиден, консоль чистая, `tsc` и сборка зелёные, ревью по диффу проходит — дефект существует только в вычисленном стиле во время исполнения. **Исключённый тупик:** `animation-play-state: paused` вместе с `opacity: 1` не работает никогда; снимать нужно саму анимацию — `animation: none; opacity: 1`.

**How to apply:** цена проверки — один скрипт Playwright на 30 строк (`page.$eval` → `getComputedStyle`); цена пропуска — неверный рецепт уходит в каждую страницу, сгенерированную с пресетами `landing`, `story`, `showcase`, и всплывает у клиента, а не у нас. MCP-браузер занят чужой сессией — это не повод пропустить: `npx playwright install chromium` и свой скрипт. То же касается демонстраций владельцу: доска направлений обязана двигаться ровно так, как будет двигаться страница, иначе она обещает несуществующее.
