Ставишь скилл из внешнего репозитория — допиши в хвост его `description` русские фразы,
на которых владелец реально позовёт скилл. Английский текст оригинала не трогай.

**Why:** автозагрузка скилла — матчинг по тексту `description`. У внешних паков он
английский, владелец пишет по-русски. Отказ молчаливый: ошибки нет, скилл просто никогда
не вызывается, и это не всплывает, пока кто-нибудь не спросит, почему им не пользуются.
Три пака подряд (Sentry, SEO/GEO, taste-skill) потребовали одной и той же правки.

**How to apply:** после копирования папки — фразы в хвост `description`, плюс строка
границы со смежным нашим скиллом («не для X — зови Y»). Скиллу, который порождает текст
страницы, туда же блок про [[project_no-invented-facts]] первым разделом тела: правило
проекта должно быть объявлено старше инструкций пака явно, внутри самого файла.
В заметку об установке записать, что правки переносятся вручную при `git pull`.

Исключённый тупик: переводить `SKILL.md` целиком не надо — тело читает модель, ей язык
безразличен, а переведённый файл потом не смержить с апстримом.
